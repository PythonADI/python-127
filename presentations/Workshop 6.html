Workshop 6

Functions, Part 2

1. Keyword arguments

Pass arguments by name and the order no longer matters.

Mixing positional and keyword

Mix them freely, but positional arguments come first.

Keywords + default values

Skip the defaults you do not care about and name the one you do.

2. Returning more than one value

return a, b sends back a tuple; the caller unpacks it in one line.

3. Return early

Handle the special case first, so the main code is not buried in else.

Return from inside a loop

Return the moment you know the answer; if the loop finishes, the code after it runs.

4. Global variables — reading

A variable created outside every function is global, and a function can read it.

Assigning creates a local

Assigning to a name inside a function makes it local, so the global is not touched.

Changing a global with global

You must say so with global (you saw this in khinkali.py).

Prefer parameters and return

Everything the function needs comes in as parameters, and everything it produces goes out through return.

def use_herbs(herbs):
    return herbs - 1

herbs = use_herbs(herbs)

5. Functions that answer yes/no

Returns True or False, so it reads naturally in an if or a while.

Return the comparison directly

No need for if ...: return True else: return False. Name such functions like questions: is_even, has_digit, is_valid.

def is_adult(age):
    return age >= 18

6. Docstrings

A string on the first line inside a function documents it. It is not executed; write one line saying what it returns or does.

def area(width, height):
    """Return the area of a rectangle."""
    return width * height

7. Putting it together: input validation

A function plus a while loop keeps asking until the answer is good. return is the way out, no break needed.
